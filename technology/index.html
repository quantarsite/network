HYDRA-X Verification Rule
Ver_L(pk_L, tx, σ_L) = 1  AND  Ver_H(pk_H, tx, σ_H) = 1
Ver_L = ML-DSA-87  (NIST FIPS 204 · Lattice / Module-LWE)  |   Ver_H = SLH-DSA-SHA2-256s  (NIST FIPS 205 · Hash-based / stateless)

A transaction is valid only if both schemes verify independently. An attacker must break two mathematically unrelated paradigms simultaneously.

Address Construction
addr = BLAKE3-256(
  pk_L ‖ pk_H)
Live on the testnet today.
Privacy Model
pk_L and pk_H are revealed only with the first outgoing transaction.

An address that only receives exposes nothing but a hash of its keys.
Quantum Security
A 256-bit hash under Grover's algorithm → 128-bit quantum preimage security.
Binding Property
Commitment is computationally binding — changing keys behind an address requires a second preimage of BLAKE3.
L3 ⏱
Temporal Expiration Engine
Mandatory key TTL at consensus level. Planned for mainnet, not active on the current testnet
PLANNED
TTL Mechanism
Design: each keypair carries a block_expiry on-chain and the protocol rejects signatures past it.
Attack Window Reduction
Even if sk_L leaks, an attacker cannot forge past the TTL without also breaking SPHINCS+ within the time window.
Migration Transaction
MigrateKey(old_pk, new_pk, σ)
Design: signed by both old keypairs, atomic renewal with no double-spend window.
Why Mandatory
Optional rotation = never rotated in practice. Mandatory TTL enforces cryptographic hygiene at protocol level, not developer discipline.

PERFORMANCE
Parallel Verification (planned)

Signature Bundle (research)
Research direction: a block-level proof covering all transaction signatures to reduce full-node validation cost. Not implemented today; every signature is verified individually.
